## Why

Solvia is a greenfield portfolio project: an agentic credit assistant for contact centers, built on Open Finance Brasil data and LangGraph, meant to demonstrate stateful agent orchestration, observability of non-deterministic systems, and LLMOps practices in a regulated fintech context. Before any regulatory RAG, human handoff, VPS deployment, or evaluation work can be built, the project needs a working foundation: the monorepo scaffold, an LLM gateway abstraction, deterministic financial tools bound to a synthetic customer identity, an MVP conversational graph with concrete per-intent behavior, a safely-streamed API, and basic observability — all runnable locally via `docker compose up` against the gateway over an SSH tunnel.

## What Changes

- Create the feature branch and add `.gitignore` as the first two actions of this change, before any other work; commit the OpenSpec planning artifacts on that branch.
- Add monorepo layout: `apps/api`, `apps/agent` (`graph.py`, `state.py`, `nodes/`, `tools/`, `prompts/`, `llm/`, `config/`), `apps/console` (scaffold only), `services/crm_mock` (scaffold only), `data/`, `rag/` (scaffold only), `evals/` (scaffold only), `infra/`, `docs/adr/`.
- Add a settings module (pydantic-settings) and an LLM factory implementing a provider port: OpenAI-compatible adapter (default, talks to the `9router` gateway via `solvia-fast`/`solvia-smart` aliases), a Google adapter (langchain-google-genai, Gemini Developer API or Vertex AI), and a fake LLM for tests. Includes per-node fast/smart tier mapping (router and compliance_guard: fast; financial_analyst and responder: smart), timeouts/retries with backoff, smart→fast degradation, and a "demo temporarily unavailable" fallback when both tiers fail.
- Add a reproducible synthetic data generator (fixed seed, and all dates derived from a fixed reference date in config — never the current clock) producing ~200 customers with Open Finance Brasil–shaped accounts, transactions, credit cards, and consents (each consent carrying a status of valid, missing, or expired), across salaried / self-employed / over-indebted / thin-file profiles. Generated output goes to `data/generated/` (gitignored); only a small set of fixture records is committed under `data/fixtures/` for tests.
- Add deterministic financial tools: income estimation, debt-to-income ratio, deterministic spending categorization (from transaction codes/descriptions), and Price/SAC amortization — pure Python, no LLM involvement, fully unit tested. CET (total effective cost) is defined as the annualized IRR of the net cash flow (amount released minus IOF and fees, versus the installment schedule), computed with `Decimal` and documented rounding rules; interest rate, IOF (fixed rate + capped daily rate, configurable), and fees come from a fictional product catalog in config, never from the LLM.
- Add an MVP LangGraph conversation graph bound to a synthetic `customer_id`: `router` (intent classification), `consent_check`, `financial_analyst`, `offer_simulator`, `responder`, `compliance_guard`, `END`, with a typed (TypedDict/Pydantic) state and a Postgres checkpointer. Defines concrete MVP behavior per intent: loan simulation and profile analysis (full data-backed path), product question (answered from the fictional product catalog; full RAG is `add-regulatory-rag`), complaint (acknowledged, with a note that human handoff is a future capability), and out of scope (polite refusal). The consent flow is concrete: `consent_check` reads the customer's synthetic consent; when missing or expired, the assistant asks for authorization and an explicit confirmation message grants a synthetic consent recorded in state (redirecting to a real consent flow is out of scope). Loan simulation uses structured-output slot extraction (amount, term in months, amortization type Price|SAC) with a follow-up question when a slot is missing or invalid; the LLM never writes numbers — all numeric values in replies are rendered from tool output via templates.
- Add a FastAPI service exposing `POST /conversations/{id}/messages` requiring `customer_id` on the first message of a conversation (persisted in state, immutable for that conversation, rejected if unknown), streaming only `node_started`/`node_finished` progress events plus a single terminal `final` event carrying the reply produced after `compliance_guard` (never raw/unguarded model tokens), and `GET /health/live` (process only) plus `GET /health/ready` (includes gateway reachability).
- Add basic LangFuse tracing and structured (structlog JSON) logging, correlated by `trace_id`, with redaction of secrets/PII.
- Compliance guardrails are deterministic where possible: PII masking (CPF, account/card numbers, phone, email) via regex and disclaimer injection via templates are fully deterministic; only approval-promise detection uses the fast-tier LLM, backed by a keyword/regex check as a safety net.
- Add `docker-compose` (dev profile) wiring `api` + `postgres`, LangFuse configured via env (Cloud by default).
- Add `.env.example` (`LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL_FAST=solvia-fast`, `LLM_MODEL_SMART=solvia-smart`, etc.), with all secrets/environment-specific values sourced only from env. Document that local development reaches the `9router` gateway only through an SSH tunnel (`ssh -L`) with `LLM_BASE_URL=http://localhost:<port>/v1`; the gateway is never exposed publicly.
- Add ADR-001 (LangGraph over CrewAI/autonomous agents) and ADR-002 (LLM access via OpenAI-compatible gateway with model aliases, app-level degradation, Vertex AI via configuration).
- Add engineering foundation: pre-commit (ruff, mypy, gitleaks), CI (lint, type-check, tests — with a Postgres service container for checkpointer integration tests — and gitleaks as a required check), a Portuguese `.github/pull_request_template.md`, `CONTRIBUTING.md`, and a `CLAUDE.md` recording the conventions below for future sessions.
- Add a blocking, read-only VPS infrastructure pre-flight assessment (`docs/infra-assessment.md`) that gates all other implementation work on a go/no-go verdict, including verification that the local SSH tunnel to the gateway works.

Out of scope for this change (tracked as future changes, in this order): `add-regulatory-rag`, `add-human-handoff`, `add-vps-deploy`, `add-llm-evals`, `add-prompt-versioning`.

## Capabilities

### New Capabilities

- `llm-gateway`: settings-driven LLM factory with an OpenAI-compatible adapter (default), a Google adapter, and a fake LLM; per-node fast/smart tier mapping (including the `responder` node on the smart tier); timeouts/retries; smart→fast degradation; graceful "unavailable" fallback; resolved-model recording for tracing.
- `synthetic-data`: reproducible (fixed-seed, fixed-reference-date) generator of ~200 synthetic Open Finance Brasil customers (accounts, transactions, credit cards, consents with valid/missing/expired status) across defined profiles, writing to `data/generated/` with committed test fixtures under `data/fixtures/`.
- `credit-simulation`: deterministic, LLM-free financial tools — income estimation, debt-to-income ratio, deterministic spending categorization, and Price/SAC amortization with CET defined as annualized IRR of the net cash flow (Decimal, documented rounding), sourcing rate/IOF/fees from a fictional product catalog.
- `conversation-graph`: MVP LangGraph orchestration bound to a synthetic customer (router, consent_check, financial_analyst, offer_simulator, responder, compliance_guard, END) with typed state, Postgres-backed checkpointing, concrete per-intent behavior, a concrete synthetic consent flow, and structured-output slot extraction for simulation requests.
- `conversation-api`: FastAPI endpoint for starting/continuing a customer-bound conversation with safely-restricted SSE progress/final events, plus split liveness/readiness health endpoints.
- `observability`: LangFuse tracing and structured logging, correlated by trace ID, with mandatory secret/PII redaction.

### Modified Capabilities

None — this is a greenfield project with no pre-existing specs.

## Impact

- **New code**: full monorepo scaffold under `apps/`, `services/crm_mock` (scaffold), `data/`, `infra/`, `docs/adr/`; no existing code is touched.
- **New dependencies**: LangGraph, LangChain, langchain-google-genai, FastAPI, Streamlit (console scaffold only in this change), fastembed (embeddings port, unused until RAG), structlog, LangFuse SDK, Postgres + pgvector, uv/ruff/mypy/pytest tooling, gitleaks.
- **Infrastructure**: read-only assessment of the existing VPS (Docker, reverse proxy, ports, `9router` gateway reachability including via an SSH tunnel) before any container is added; no VPS changes are made in this change.
- **CI/CD**: new GitHub Actions workflow(s) for lint/type-check/tests (with a Postgres service container)/gitleaks; a Portuguese PR template; no deploy workflow yet (deferred to `add-vps-deploy`).
- **Process**: establishes `.gitignore`, the trunk-based branching, Conventional Commits, and PR conventions that all future changes (including the ones listed as out of scope) must follow. Manual steps deferred to the repository owner: branch protection on `main` requiring CI checks, GitHub secret scanning, and push protection.
